# Infinity Hex Games 向量桌游 — 官网

Next.js 16 · React 19 · TypeScript · 零 CSS 框架（手写设计系统）

```bash
npm install
npm run dev      # http://localhost:3000
npm run build && npm start
```

Node ≥ 20.9。Turbopack 已是 Next 16 的默认构建器，无需 `--turbopack`。

## 1. 交付前必做的五件事

1. **放 logo**：把 logo 放进 `public/`，命名 `logo.*` 即可——**`.png` / `.svg` / `.webp` / `.jpg` 都行，扩展名不重要**（见 §3.6）。layout 在**服务端**解析它在不在、是什么格式，在就用它，不在就用内置的 SVG 六边形标志。不用改任何代码，也不会在网络面板里留下 404。

   > **如果 logo 是白色或单色的**：宣纸底的顶栏上它会直接消失。把 `src/brand.ts` 里的 `logoPlate` 改成 `true`，标志就会坐在朱砂六边形底板上（和 Hero 里那枚印章同一个视觉逻辑）。一行的事。
2. **换掉示例游戏**：`content/games/` 里带 `sample: true` 的 6 个文件是占位，删掉或替换。卡片上的「示例数据」角标会随之消失。
3. **换掉示例证言**：`content/testimonials.json` 里六条全部带 `sample: true`，页面上也如实标着「示例内容」。**这些话是写出来演示版式的，不是任何人真的说过的**——上线前必须换成拿到书面授权的真实引述，或者把这个 section 删掉。人名与公司名都是虚构的，没有借用真实合作方的名义。
4. **换掉占位人像与封面**：`public/people/*.svg` 与 `public/games/*/cover-*.svg` 由 `scripts/make-placeholders.mjs` 生成（见 §3）。有真图就直接替换文件，或把 `content/team.json` 的 `photo` 与 md 里的 `cover` 指到新路径。
5. **让法务过一遍** `src/content/legal.ts` 里的三份政策，并更新 `UPDATED` 日期与公司主体信息。它们如实描述了当前代码的行为，但仍是草稿。

## 2. 目录结构

```
content/

  team.json           ← 团队名册（/about 页面）
  testimonials.json   ← 合作方证言（口碑 section）
  partners.json       ← 合作伙伴蜂巢
scripts/
  make-placeholders.mjs ← 生成占位封面与占位人像
public/
  logo.png            ← 你放进来的真实 logo（可选，缺失时自动回退）
  games/<slug>/       ← 每个游戏的封面图（md 里用 cover 指过来）
  people/<id>.svg     ← 团队与证言的人像
src/
  proxy.ts            ← 语言路由（Next 16 把 middleware 改名为 proxy）
  app/[locale]/       ← 页面：首页 / about / games/[slug] / legal/[doc]
  components/         ← Hero、转场、区块、Cookie 同意
  content/legal.ts    ← 隐私 / Cookie / 条款
  i18n/
    copy.ts           ← 全站营销文案（中英两份，结构相同）
    dict.ts           ← 品牌 / 无障碍 / Cookie / 法务文案 + 合并 copy.ts
  lib/games.ts        ← Markdown → 数据（build 时执行）
  lib/milestones.ts   ← 历程 JSON → 数据，并把众筹数字从 md 里取出来
  lib/team.ts         ← 团队 JSON → 数据
  styles/             ← base / hero / sections 三张表
```

## 3. 新增一个游戏

在 `content/games/` 里新建一个 `.md`，**下次 build 时首页卡片和详情页会自动出现**——没有注册表，不用改代码。

```markdown
---
slug: my-game            # 可省略，默认取文件名
order: 3                 # 排序
kind: original           # original | localised
status: funding          # shipping | funding | upcoming | licensing
color: "#1F6E64"         # 占位封面与强调色
cover:                   # 封面图，中英各一张；只写 en 时中文页自动复用
  en: /games/my-game/cover-en.jpg
  zh: /games/my-game/cover-zh.jpg
sample: false            # true 时卡片显示「示例数据」角标
year: 2026
designer:                # 也可以只写一个字符串
  zh: 某某
  en: Someone
players: "2–4"
time: "60–90"
age: "12+"
weight: 3.2
funding:
  amount: 1284000
  currency: CNY
  backers: 3120
  stretch: 28
  platform:
    zh: 摩点
    en: Modian
title:
  zh: 中文名
  en: English Title
tagline:
  zh: 一句话介绍
  en: One-line pitch
tags:
  zh: [策略, 版图]
  en: [Strategy, Area control]
---

中文正文，正常 Markdown。

<!-- @en -->

English body. 缺这一段时会自动复用中文正文。
```

**一个文件装两种语言**，正文用 `<!-- @en -->` 这一行分隔（在任何 Markdown 编辑器里都不可见）。

### 首页数字是算出来的，不用手改

Hero 那一排「众筹总额 / 累计支持者 / 解锁目标」以及 kicker 里的项目数，全部由 `getTotals()` 在 build 时从所有 md 汇总。加一款游戏、改一个数字，首页自己就更新了。

**带 `sample: true` 的条目不计入金额、支持者、解锁目标**——占位数字绝不能进标题总计。但它们照常计入「项目数」，因为那只是目录里有几条。「平均响应 48 小时」不是能从 md 推出来的东西，仍留在 `dict.ts` 里。
### 封面图只写一次，全站都用它

`cover` 里的图会被**首页牌弧、图片墙、作品卡片、详情页**同时取用——不用在四个地方各放一份。写成 `{ en, zh }` 两张，英文页取 `en`、中文页取 `zh`；**只写 `en` 时中文页自动回退到它**，所以没有中文版封面也不会开天窗。

横图、竖图、方图都行：卡片与墙按固定比例裁切（`object-fit:cover`），详情页则按图片本来的形状显示在一块底色板上——竖图不会被腰斩，横图也不会被拉长。

封面留空时会用 `src/lib/cover.ts` 生成的 SVG 占位图，挂在真实的 `<img src>` 上——换真图就是换 `src`。
金额会按语言自动格式化：`¥199.6万` / `¥2.00M`。
`designer` / `publisher` / `funding.platform` 既可以写成一个字符串，也可以写成 `{ zh, en }`——英文页就不会再冒出中文。

## 3.5 占位素材：一条命令重新生成

```bash
node scripts/make-placeholders.mjs
```

它读 `content/games/*.md`、`content/team.json`、`content/testimonials.json`，把对应的占位图写进 `public/`。**md 是唯一事实来源**：脚本只生成 `cover.en` / `cover.zh` 里写着的那些路径，所以文件和引用不可能对不上。

里面有两条规则值得记住，因为它们各自对应一个真实踩过的坑：

- **要紧的东西一律放中间。** 封面同一张图会被用在 5:7 的卡、3:2 的手机卡、以及详情页的原始比例上，`object-fit:cover` 是从中心裁的。第一版把标题左对齐压在底部，结果 5:7 一裁，正好把标题裁掉一半——首页牌弧和图片墙上就出现了「oyang」「rden Above」这种半截字。现在标题排在**宽度中间 56%、高度中段**，怎么裁都还在。
- **SVG 里不能有裸 `&`。** SVG 是 XML，`Rivers & Ranges` 里那个 `&` 会让整份文件解析失败，浏览器一声不吭地显示成裂图。脚本统一走 `esc()`。

人像是有意做成「一眼看出是占位」的：品牌色底 + 六角取景框 + 姓名首字母 + 一个极淡的人形剪影 + 底部小字 `PORTRAIT`。有真照片时直接覆盖同名文件即可，尺寸按 1:1 裁。

## 3.6 换图：把文件丢进去就行，不用改 JSON

站内每一张图都是数据里的一条普通路径——游戏的 `cover`、成员的 `photo`、伙伴的 `logo`、根目录的 `logo`。这些路径统一走 `src/lib/asset.ts` 的 `resolveAsset()`，它**忽略你写的扩展名**，按下面的优先级去 `public/` 里找真正存在的那一个：

```
.webp → .avif → .png → .jpg → .jpeg → .gif → .svg
```

也就是说：

```
content/team.json   photo: "/people/andy.svg"     ← JSON 里写的
public/people/andy.png                            ← 你丢进去的
页面渲染                /people/andy.png            ← 实际用的
```

生成的占位图是 `.svg`，排在**最后**，所以**任何真图都会自动盖过占位图**。「Andy, founder, at the studio playtest table」那张、团队八张、证言六张、八个封面、伙伴 logo、以及网站 logo，全都是这个规则——把 `andy.png` 拖进 `public/people/` 就换完了，JSON 一个字都不用动。路径也可以干脆不写扩展名（`"/people/andy"`）。

找不到任何文件时返回 `undefined`，各组件退回自己的兜底（字母标、生成的封面、内置 logo），不会出现裂图。

> 唯一的例外是 `src/lib/cover.ts` 里那个 data-URI 占位封面——它只在 md 完全没写 `cover` 时才出现，属于兜底而不是素材。

## 4. 中英双语

- 路由是 `/zh` 与 `/en`，两种语言都在 build 时静态生成。
- `src/proxy.ts` 在边缘处理 `/` → `/zh` 或 `/en`：**先看 `ihx_locale` cookie，没有就解析 `Accept-Language`**（带 q 权重；中文任意变体 → zh，其余 → en）。深链接会被完整保留：`/games/agemonia` → `/en/games/agemonia`。
- 导航栏的「中 / EN」开关写 cookie 后跳到对应语言的同一页面。
- 文案分两处：**营销文案在 `src/i18n/copy.ts`**（`copyZh` / `copyEn` 结构完全对称，改一处必须改两处，TypeScript 会替你盯着），**品牌 / 无障碍标签 / Cookie / 法务在 `src/i18n/dict.ts`**。游戏、历程、团队、证言的文案在 `content/` 里，互不干扰。
- 全站文案是按 **B2B 口径**写的：面向发行商与设计师，讲授权范围、术语表、打样规格、印量与运费、交付日期、48 小时回复，同时保持一家年轻桌游公司该有的语气。`Portfolio` 这个词已经换掉了——发行与授权行业里通用的说法是 **Catalogue（作品目录）**，英文导航用的是 **Titles**。
- 英文页上**不会漏中文**：`designer` / `publisher` / `funding.platform` / 伙伴名 / 副标题全部走双语字段，语言开关的「中 / 切换到简体中文」是唯一的例外（那是惯例，不是漏网）。
- 英文里那个滚动词（`rollers`）左右会自动留一个词距（`html[lang="en"] .roller{margin-inline:.3em}`），中文不留——中文加空格反而会在句子里开洞。

## 5. Cookie 与合规

以欧盟口径为基线（同时满足美国各州法）：

- 非必要 Cookie **在明确同意前一个都不设**。
- 分类颗粒化，**默认全关**，没有预勾选。
- 「全部拒绝」与「全部接受」**同样大小、同样显眼、同样一步到位**（已实测两个按钮的类名与宽度完全一致）。
- 页脚「Cookie 设置」随时可撤回；另有「不出售或共享我的个人信息」入口（CPRA）。
- 同意记录带版本号与时间戳，180 天后重新询问。
- **尊重 GPC 信号**：浏览器发送 `Sec-GPC: 1` / `navigator.globalPrivacyControl` 时，自动记为拒绝并且不弹窗。

接分析工具时，**不要无条件加载**，挂到同意事件上：

```js
window.addEventListener('ihx:consent', (e) => {
  if (e.detail.analytics) loadAnalytics()
})
// 已经同意过的老访客：
if (window.__ihxConsent?.analytics) loadAnalytics()
```

当前站点确实没有装任何分析或广告脚本——Cookie 政策里是这么写的，加工具前请同步更新那一段。

## 6. 动效与性能

- **一个 rAF 循环**（`src/components/Motion.tsx`）供全站订阅；没有订阅者时自动停摆。
- **一个滚动数据源**：只有一个 passive 监听器，它只记录 `scrollY`，不读布局；所有 `getBoundingClientRect` / `offsetTop` 都在 rAF 回调里读，天然批处理。（之前是五个组件各自监听 + 各自读布局 = 每次滚动五次强制重排，这是卡顿的主因之一。）
- 没有动效开关按钮——系统 `prefers-reduced-motion` 就是唯一开关。关掉是真静止：牌弧变静态弧、墙变静态网格、canvas 停笔、转场直接隐藏。
- 所有动画只碰 `transform` / `opacity`；canvas 限 DPR ≤ 1.5，离屏时直接 `visibility:hidden`（不只是停止绘制，连图层都不再合成）。
- 六边形晶格拆成两张 canvas，静态底图只画一次，上层只画亮起的格子。
- **晶格的渐隐是画进像素里的，不是 CSS mask**。用 `mask-image` 遮一张全屏 canvas，会让浏览器每帧重新合成一整个带遮罩的图层——实测这是全页面最贵的一件事。改成在绘制时按同样的曲线乘 alpha，代价为零。
- 图片墙原本用两层 mask + `mask-composite` 罩在一个 3D 子树上，同样很贵；现在只保留水平方向的 mask，垂直渐隐改用普通渐变层。
- `content-visibility:auto` 试过又**撤掉了**：它的 `contain-intrinsic-size` 是个估值，于是每个第一次滚进视口的 section 都会改变文档高度、把下面的东西整体推走——锚点会漂、滚动条会跳。它省下的那点开销远不及 canvas 那一刀，正确性优先。

实测（同一台机、同一浏览器，全页滚动 150 帧）：中位帧间隔 **33.4ms → 16.7ms**，超过 32ms 的帧 **125 → 40**。JS 自身开销一直只有 1.1–1.7ms/帧，瓶颈从来不在逻辑，在合成。

### 无障碍

- 图片墙 100 张 tile 全部 `aria-hidden`，读屏用户拿到墙上方一份干净的目录列表——不会被 100 个 tab 停靠点淹没。
- 灰阶 token 按 WCAG AA 校准过；跳转链接、朱砂焦点环、语义标签、`lang` 标注齐全。
- 系统开启「减少动态效果」后全站真静止，不是"动画变快"。

### 段落转场：落子

上一版是翻面色带，动画跑完之后留下一条平平的条子——那是"动画的残留"，不是设计。这一版反过来做：**静止状态才是设计**。

两个 section 沿一条互锁的六边形边界相接（上一节的色块被压成一排半嵌的六角）。接缝进入视口时这排格子还不在，它们从上方一枚枚落下、带一点回弹地就位，直到互锁完成。动画结束后什么都没剩下，因为被动画进来的那条边界本身就是最终形态。中央那枚格子上站着一个**米宝或骰子**（`piece="meeple" | "die"`，页面上交替）。

**每一格都装着一件配件**——米宝、六面骰、木块、卡牌、六角 token、棋子、八面骰、金币、沙漏，循环取用；中央那格放你在 `piece` 里指定的那个，尺寸大一号、颜色更实。图标颜色按上一节的底色亮度自动切明暗（亮底用泥金，暗底用宣纸白），所以同一个组件在明暗接缝上都成立。

一条接缝 = 1 个矩形 + 约 20 个 clip-path 六角，靠一次 class 切换 + CSS `transition-delay` 阶梯驱动，每帧零开销。

### 滚动叙事：铺开一局（`<Process>`）

340vh 的滚动跑道 + sticky 舞台。往下滚时：六边形棋盘**从中心一格格发出来**、卡牌／米宝／木块／骰子分五层以不同速率视差移动、左侧四步文案随之推进。全部挂在**一个**滚动进度值上（在共享 rAF 里读），没有额外监听器。棋盘每一格用 `clamp()` 把自己那一小段进度换算成落位与缩放，纯 CSS 计算。

减少动效时它塌成一块完整的棋盘 + 一个普通四项列表。

**它在每个尺寸上都是同一套 scrollytelling**，只换排布和视差幅度，而不是在小屏退化成静态堆叠：

| 断点 | 排布 |
|---|---|
| ≥1081 | 左文右图两栏，视差 ×1 |
| 1080↓ 竖屏（iPad 竖放） | 标题 → 舞台 → 四步，竖排居中，视差 ×0.52 |
| 1080↓ **横屏**（iPad 横放、小笔电） | 屏幕宽而矮，重新回到两栏 |
| ≤640 手机 | 标题 → 舞台 → **只显示当前一步** + 四段进度条，视差 ×0.34 |
| ≤640 且高 ≤700（SE / 手机横屏） | 舞台再缩一档 |

舞台的尺寸**只由宽度决定**（`width:min(100%, var(--art))` + `aspect-ratio:1/1`）。中途试过配 `max-height`，结果宽高比失去可解析的确定轴、整个盒子塌成 0 高——别再加回去。

### 滚动叙事：长桌（`<History>`）

公司历程没有做成一列时间轴，而是做成**一张长桌**：section 高 520vh，舞台 sticky，**纵向滚动驱动横向轨道**，六个里程碑从固定在屏幕中央的"读取头"（那条泥金竖线）前面走过。

每张卡片每帧只拿到两个数：`--d`（自己离读取头有多远，带正负号，以屏宽为单位）和 `--ad`（它的绝对值）。旋转、后退的 Z、透明度全部由这两个数推出来，所以整排卡片是**一排真的有纵深的实物**，不是一个滑动列表。六角号码牌上的朱砂描边随 `--ad` 连续变厚——"当前"是一个连续状态，不是一次 class 翻转。

背后三层各走各的速率：色晕、六角网、以及那个**巨大的年份**（描边字，随读取头换页交叉淡入）。底部一排六角 pip + 进度条同时充当"你确实在滚"的提示。

减少动效时它整体塌掉：不再 pin，不再 3D，变成一条普通的横向可滚动卡片带（`body.no-mo .hist`）。

| 断点 | 处理 |
|---|---|
| ≥1081 | 卡片 352px，跑道 520vh |
| 1080↓ | 卡片 ≤320px，跑道 480vh |
| ≤760 | 卡片 76vw，隐藏导语，跑道 440vh |
| ≤520 | 卡片 82vw，pip 去掉年份只留形状，跑道 400vh |
| 高 ≤620（手机横屏） | 正文钳到 3 行，年份缩小 |

### 历程（`<History>`）：改 JSON，其余自己算

> 背景里那个巨大的年份原来只有 14% 的描边、在墨色上基本看不见。现在是 30% 描边 + 一点点填充——卡片本来就是实心的挡在它前面，不会打架。



内容全部在 `content/milestones.json`，改它就够了，别的都会跟着走：

| 你写的 | 自动得到的 |
|---|---|
| 数组里加/删一条 | 六角号码牌 `01…NN`、底部年份 pip、进度条分母 |
| —— | **section 高度**：`--rows` 由条目数写到元素上，CSS 里 `height:calc(var(--rows) * 78vh + 46vh)` |
| `stats: [{ game, field }]` | 从 `content/games/<slug>.md` 里取真实数字并按语言格式化（`¥211.9万` / `1,173` / `53`） |
| `stats: [{ label, value }]` | 直接照写的双语字面值 |

也就是说众筹金额、支持者数、解锁目标数**在整个站点只存在一份**（游戏的 md 里），历程卡片、Hero 数据条、详情页三处都从那儿取。改一个数字，三处一起变；漏改造成的自相矛盾在结构上就不可能发生。

卡片本身是**不透明**的。上一版用了 10% 的半透明白 + backdrop 模糊，叠在会动的六角网和巨大的描边年份上，正文要眯着眼看；现在是实心的提亮墨色 + 一道暖色发丝边，当前卡顶部还有一条随 `--ad` 亮起来的朱砂线。巨大的年份也从「穿过卡片」挪到了「卡片上方那条带子里」。

### 口碑（`<Voices>`）：一张会转的圆桌

`content/testimonials.json` 驱动。发言人的头像排成一行六角 token，上方的引述交叉淡入；引述下面那条细线是当前发言人还剩多少时间。

三个细节：

- **鼠标碰到、或者键盘 focus 进去，计时立刻停。** 正在读的时候被轮播翻页是最糟的体验。
- 计时走的是共享 rAF 的 `dt` 累加，不是 `setInterval`——后者会和动画时钟越走越偏。
- 所有引述叠在**同一个 grid 单元**里，所以切换时块高度不变，页面不会跳。

离开视口就整个停下；`prefers-reduced-motion` 下不自动轮播，只保留点击切换。

### 团队页（`/[locale]/about`）

`content/team.json` 一个文件就是整页：加一个人就多一张卡。`lead: true` 的那位排在最前，宽屏下横跨整行、图文左右排。排序是「lead 优先 → 按 `since` 年份 → 文件顺序」，所以不用手工维护次序。

### 为什么首页不写 "Est. 2024"

创立年份是一枚**传承徽章**，而传承恰好是一家 2024 年成立的公司唯一赢不了的东西——把它挂在首屏，等于主动邀请对方拿你和一家做了三十年的发行商比。所以 Hero 上那枚 pill 换成了**交付记录**：

```
2 次众筹 · 全部按期交付      2 campaigns · 100% delivered
```

`{c}` 是从游戏 md 里数出来的众筹次数，不是手写的。这是发行商真正想知道的那件事——你交付过几次、有没有拖过。

年份**没有被藏起来**：它仍然在「历程」的第一条（2024 春 · 公司成立）和 `/about` 的公司信息里。区别是在那两处它是**上下文**，读起来是势头；挂在首屏就成了徽章，读起来是资历不够。英文顶栏的副标题同样从 `Tabletop · Since 2024` 改成了 `Tabletop Publishing`。

想改回去：`src/i18n/copy.ts` 里 `hero.est` 一行。

### 品牌标记只有一份：`src/components/mark.ts`

顶栏 logo 的兜底图形、和 Hero 标题旁那枚印章，现在共用同一组路径，所以两者不可能画歪成不同的样子。

那枚印章**是印章，不是 logo**——它保留 `向量` / `之印` 的中文页写法；英文页里放的是品牌的 ∞ 标记。之前那个 ∞ 是手画的，右半边比左半边低一点、宽一点（你看出来了），现在换成两段**互为镜像的三次贝塞尔**：右侧每个控制点都是左侧对应点关于 x = 50 的反射，整体对 y = 50 也对称。

`src/brand.ts` 里的 `sealGlyph` 可以改成 `'mark'`（两种语言都用 ∞）或 `'seal'`（两种语言都用印文）。

### 图片墙的每一张都能点

墙上的封面现在是 `<a>`，指向对应作品的详情页；鼠标悬停时整行会暂停（本来就有），标题条带出一个箭头。

它们**故意不进 tab 顺序**（`tabindex="-1"` + `aria-hidden`）。墙上有 5 行 × 双份循环 ≈ 100 个 tile，指向的却只是同样那十个目的地；把它们全塞进焦点链，键盘用户要按一百次 Tab 才能走完一段纯装饰的跑马灯。真正可访问的那份列表就在墙下面一屏（`#games` 的卡片网格），每张卡都是正常的链接。这是"装饰性副本"的标准处理方式。

### 视差：不止一个 section

`<Parallax>`（`src/components/Parallax.tsx`）是一层装饰面，接 `y` / `x` / `rotate` / `scale` / `fade` 五个参数，含义都是"每滚过一屏走多少"。作品、业务、伙伴、关于、合作 band、详情页头图后面各挂了 2–3 层，速率各不相同，于是这些区块有了纵深而不是一块平板。

两个实现细节值得记一下：

- **静止位置只量一次**（挂载时 + 文档 reflow 时），不是每帧量。`getBoundingClientRect()` **包含 transform**，每帧读一次再写一次，等于把自己上一帧的位移喂回下一帧——会漂走。
- 每帧只写 `transform` / `opacity`，**没有任何一层用 mask**。给一层全宽元素上 `mask-image` 会让浏览器每帧重新合成整层，这正是之前把滚动卡出锯齿的那件事。

手机上线稿类的面（六角网、印章、六角环）直接不渲染，只留色晕——那个宽度上正文才是主角。

### 页面被钉住时，怎么让人知道滚动是有效的

`<Process>` 与 `<History>` 都会把页面钉住一段时间。钉住期间如果画面只是"慢慢变"，用户会以为页面卡了，所以两处都给了**明确的、会动的回执**：

- 一个 `NN/04` 计数器，走到哪一步就是几；
- 一条随滚动实时填充的进度条；
- 一句「继续滚动」+ 一个上下轻推的箭头，钉住时淡入、走到尽头淡出（`--cue`）。

另外四步文案本身也改成**连续**的：每一步都有自己的 `--sp`（0→1 是"正在经历这一步"），号码牌是六角 token，轮到它时翻正、变朱砂、数字反向旋回来；下面的细线按 `--sp` 横向刷过去。以前是"当前那步亮、其余暗"的二值切换，现在整栏都在动。

（`--sp` 的透明度曲线故意做得很陡：走进这一步的四分之一就已经全亮。否则"刚开始的当前步"会比"已经走完的上一步"更暗——那是反的。）

### 合作伙伴：把格子做大

原来蜂巢格子上限 148px，logo 只能占其中 64%——太小、看不清。现在的做法：

- 格子上限 **268px**，列数由容器宽度决定（2 → 6 列）；
- 列数不是硬编码的。`pickCols()` 会把每一种可行列数都试一遍，取**最后一行最齐整的那个最宽解**——蜂巢的行是 `n / n−1` 交替的，列数选错就会剩下半排空格；
- logo 尺寸按**六边形的腰**来算：尖顶六角只有在 25%–75% 高度之间才有满宽，那一段正好是 1.73:1 的横长方形，对 logo 是理想比例。所以图按 `width:82%; max-height:46%` 排，而不是"塞进整个六角"；
- 默认只做半程去色（`grayscale(.5)`），hover 才全彩——之前默认全灰 + 62% 不透明，品牌辨识度损失太多；
- 有真 logo 的格子在下方常驻品牌名（不再是 hover 才出现，手机上根本没有 hover）；占位字母标本身已经写了名字，就不再重复。

### 滚动进度：骰子（以及 6 节以上怎么办）

右侧的 `<DiceRail>` 不是进度条，是真的骰子。d6 只能数到 6，所以它按页面长度自己换器具——就像在真桌子上一样：

| section 数 | 显示 |
|---|---|
| ≤ 6 | 一颗 d6，骰面就是第几节 |
| 7–12 | **两颗 d6 相加**（第 9 节 = 5 + 4） |
| > 12 | 一枚会翻面的编号六角 token——骰子隐喻体面退场，而不是假装自己数得过来 |

加 section 时不用改组件，它自己切换；旁边的 `NN/NN` 一直在，永远不会产生歧义。

**当前首页 10 节**——首屏 / 图片墙 / 作品 / 流程 / 业务 / 历程 / 口碑 / 伙伴 / 关于 / 合作——每一节让骰子加一，所以现在走的是"两颗骰子相加"那一档。节次表在 `src/app/[locale]/page.tsx` 的 `<DiceRail ids={…} total={…}>`：**加一节就往 `ids` 里按文档顺序补一个 id，并把 `total` 加一**，别的都不用动。

## 8. Hero 的牌弧

牌弧**故意溢出栏位**：`.hero-stage` 带负 margin 顶出页面 gutter，最右一张牌被 `.hero{overflow:hidden}` 裁掉一半——设计上就是要它冲出框。

卡片之间**不设 z-index**。整个扇形在 `preserve-3d` 上下文里，浏览器按各自真实的 `translateZ` 排序，而 translateZ 随弧度连续变化。之前用整数 z-index 是它们滚动时会"跳层"的原因。

进出场用一个 `life` 值（smoothstep，`EDGE`/`FADE` 两个常数控制）**同时**驱动透明度、缩放和 Z——所以一张牌是"走过来"的，不是"出现"的。实测每帧透明度最大变化 0.064、缩放 0.011，接缝处不会再有突变。

**整副牌在页面滚动时不淡出。** 它只跟着页面往上飘一点点，透明度始终是 1——哪怕屏幕顶端只剩一角，那一角也还是清清楚楚的牌。只有当它完全离开视口时，`IntersectionObserver` 才让它停下来歇着（threshold 0 = 只要露出一丝就继续活着）。

## 10. 响应式

实测过的断点：320 / 360 / 390 / 412 / 480 / 540 / 640 / 768 / 834 / 900 / 1024 / 1180 / 1194 / 1280 / 1440 / 1512 / 1920 / 2560，首页、英文首页、两个详情页、法务页各滚一遍——**没有任何一处横向溢出**，也没有小于 24px 的可点区域。

这一轮修掉的：

- **`.sec-head` 在 900px 以下改成单列。** 它原本一直是"标题 + 导语"两栏，平板和手机上两边互相挤成每行两个词。
- **320px 一档的顶栏。** 英文站的 wordmark + 语言开关 + 汉堡按钮加起来超过 320，动作区被挤出了右边缘。现在 ≤380 收窄 wordmark、≤330 只留标志——**动作区永远不许被挤出去**。
- **英文标题与朱砂印。** `Unleash the Saga.` 是 `nowrap` 的一整行，手机上会把印章顶出屏幕（被 `overflow:hidden` 切掉）。英文标题字号改为按栏宽而不是按视口计算，印章在 ≤640 也缩一档。
- **iPad 竖屏的流程区**先前被固定顶栏压住了 eyebrow，现在 sticky 舞台自己留出 `--hdr-h`，舞台尺寸也收到 `min(34svh, 46vw)`。
- **Hero 在 iPad 横屏保持两栏**（900–1180 且宽高比 ≥1.05），不再堆成一列把牌弧推到折叠线以下；数据条在 ≤820 改成 2×2。
- 手机上作品卡的封面从 4:5 改成 3:2，一屏能看到的条目多一倍。

有几个元素会"越界"但都是故意的，且都被父级 `overflow:hidden` 裁住：`.wall-glow`、`.hero-stage`（牌弧本来就要冲出 gutter）、`.seam-row`、以及蜂巢格上的 `.glint`（被 `clip-path` 裁在六角内）。
